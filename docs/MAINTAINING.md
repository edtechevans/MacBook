# Maintaining the MacBook Productivity Learning Hub

## Content accuracy first

Each walkthrough should be tested against current vendor help and preferably a school-managed MacBook. Record relevant app/OS version, account type, and any managed restrictions. Never advise colleagues to disable required security settings.

Keep each lesson one goal with three short sequential actions, an unambiguous place to start, a safe try-it exercise, optional version caveats, and a targeted official HTTPS support page. Avoid vague phrases such as "simply" or "just click".

## Visual guidance, screenshots and video

The current site displays **conceptual UI diagrams**; these are intentionally labelled as illustrative and are not exact screenshots. Do not replace them with AI-generated imitations of actual app screens.

For genuine annotated screenshots:
1. Capture the exact OS/app version, with school-compliant permissions.
2. Remove personal mail, student details, school-confidential content and other private information.
3. Crop to the relevant task and number the actual clickable controls to match the written steps.
4. Include alt text identifying the target action, not merely "screenshot".
5. Save optimized files in assets/screenshots/LESSON_ID/step-1.webp, step-2.webp, etc.
6. Record version/date and retain the text-based alternative.
7. For videos, include captions and a full written transcript; never autoplay.

## Accessibility review

- Check at 320px wide, 200% browser zoom and landscape phone orientation.
- Contrast at least 4.5:1 for ordinary text and 3:1 for large text.
- Clear focus indication and keyboard access to every control.
- Native dialogue focus, Escape and browser Back behaviour.
- Respect reduced motion; voice playback must always be optional.
- Print full instructions, not merely lesson cards.
- Test "I can't find it" content where account/version differences apply.
- Use no colour-only status, hidden critical steps or instructional animations without controls.

## User testing

Recruit at least one new Mac user, one confident Mac user, and one faculty colleague who missed the PD. Ask them to find and complete: screen recording, scheduled Outlook email, Teams notification change, Chrome tab restoration and saved lesson retrieval. Record task completion, mistakes, confidence and repeatability.

Automated axe checks are useful, but are not the same as user-centred evidence or certification.

## Privacy and language

Local browser data holds lesson IDs and interface preferences only. Export files have no user identities or school data. The Chinese and Korean interface navigation strings do not imply translation of the full lessons; technical translation requires independent review.

## Release process

1. Validate source instructions.
2. Run static and browser checks.
3. Inspect desktop and mobile screenshots in workflow artifacts.
4. Check the major flows with keyboard and screen reader manually.
5. Deploy main and confirm Pages run succeeds.
6. Confirm the live website loads and core interactions work.
